# Bug hunt — 2026-08-04 findings and fixes

Review scope: `src/dashboard.py`, `src/execution_chart.py`, `src/pnl_card.py`,
`src/db.py`, `src/stats.py`, `src/sources.py`, `architecture_v2/`, plus the
peripheral apps. Baseline: 1006 tests passing (full suite).

## Fixed (3 bugs)

### 1. [P1] HL privacy leak in the dashboard events table
- **File:** `src/dashboard.py` (`snapshot_payload`, consumer event broadcast)
- **Impact:** The public dashboard's events table (and the raw `/ws` payload)
  sent REAL Hyperliquid prices/sizes/timestamps to browsers. The JS reads
  `e._disp` per row and falls back to `t.price` when missing; the `_disp` was
  being attached to the payload root, never to each event item, so every event
  row rendered real HL values on an internet-reachable port.
- **Fix:** New `_recent_event_payload()` serializes each event with a per-row
  `_disp` dict AND strips the real numbers from the serialized trade dict
  (fail-closed on error). Used by `snapshot_payload` and the event broadcast.
  The "last event" JS label now prefers `_disp.ts`.
- **Tests:** `test_events_payload_serializes_per_event_disp_and_strips_real_hl_values`.

### 2. [P2] Wrong close card via `closed_trades[0]` race
- **File:** `src/dashboard.py` (consumer CLOSE branch)
- **Impact:** After `await record_realization(...)`, the code read
  `closed_trades[0]` to find the card it just wrote. The reconciler's
  silent-close backstop runs concurrently and can insert its own row at index 0
  during those awaits → the close alert could send a **different coin's** card
  image (or none).
- **Fix:** Use the card path returned by `record_realization` itself
  (`(_close_result or {}).get("card_path")`).
- **Tests:** `test_close_alert_uses_record_realization_card_path_not_shared_list_head`.

### 3. [P2] TOCTOU race in `record_realization` dedup
- **File:** `src/dashboard.py` (`record_realization` dedup guard)
- **Impact:** The fill consumer and the reconciler's silent-close backstop run as
  concurrent tasks. Both could pass the `_recorded_realizations` membership
  check before either awaited, then both write → **duplicate in-memory
  `closed_trades` rows** → double-counted PnL in stats until restart.
- **Fix:** Claim the fill-id keys synchronously (no await between membership
  check and set) at the top of the guard; also drop `|None` placeholder keys so
  two id-less fills can't falsely collide, and guard the `event_uid` fallback.
- **Tests:** `test_record_realization_claims_dedup_keys_before_any_await`.
